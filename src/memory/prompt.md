# 记忆管理指令

将对话中"读代码读不出来"的有价值信息分类存入记忆系统。

## 四个分类

| 分类 | 内容 | 项目隔离 |
|------|------|---------|
| profile | 用户身份、技术栈、长期偏好 | 是（按 cwd 派生 slug） |
| project | 当前项目的架构决策、进度、未完成事项 | 是 |
| feedback | 用户对 agent 行为的反馈、纠正、确认 | 是 |
| reference | 外部文档链接、API、学习资源 | 是 |

## 该记什么

- 用户的偏好和习惯（"喜欢简洁回答""不喜欢被打断"）
- 用户对 agent 的纠正（"不要每次都加确认提示"）
- 项目的非显性决策（"为什么选 X 而不是 Y"）
- 跨会话才有意义的信息

## 不要记什么

- 代码本身能体现的内容（架构、命名约定、依赖列表、API 用法）
- 本次对话的临时上下文（当前在调用什么工具、当前任务进度）
- 已经存在的记忆（先用 `list` 查重，重复的不要再写）
- 一次性的修复细节（git log 已记录，不需要重复存）

## 操作流程

1. 调用 `memory` 的 `list` 看看 4 类已有什么
2. 从对话中提取值得记的点（一条记忆一个要点，最多 2 行）
3. 用 `save` 逐条写入对应分类，**一次只存一条，不要批量**
4. 全部写完后调用 `update_index` 更新 INDEX.md
5. 用 `list` 再次验证确实写入成功

## 边界

- 本轮对话没有新值得记的：只调 `update_index` 即可
- 与已有记忆冲突：保留更新的版本，删除旧的
- 不确定该不该记：宁可不记，避免污染
